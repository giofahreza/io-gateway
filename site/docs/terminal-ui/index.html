How-to guides

Terminal UI and animated themes

Use when
Local or remote gateway management with iogw
Updated
November 17, 2026

One terminal client, two ways to see your gateway. Use the normal management UI on its own, or add separately downloaded scene packs for a Café, Office, or Station overview. Accounts, authentication, and management actions are shared.

Choose downloads, not another application

The standard iogw binary includes the lightweight renderer, but not the optional artwork or an extra runtime. There is no separate animated executable or installer. The normal UI always opens first, even with packs installed.

Install without animation

Install the gateway and explicitly include its terminal client. The installers select the native archive and verify its checksum. Rust, Docker, and administrator access are not required for a published release.

Linux and macOS

bash -c 'set -o pipefail; curl -fsSL https://github.com/giofahreza/io-gateway/releases/latest/download/install.sh | sh -s -- --with-iogw'

Windows PowerShell

Invoke-WebRequest https://github.com/giofahreza/io-gateway/releases/latest/download/install.ps1 -OutFile ./install.ps1
& .\install.ps1 -InstallIogw

The installer also installs the gateway. Follow its prompts for port, autostart, and start-now choices. If it added the binary directory to PATH, reopen your terminal. Then launch the normal UI:

iogw
# Explicit equivalent:
iogw tui

Do not use --without-iogw for a non-animated TUI: that flag skips the terminal client entirely and installs only the gateway. You do not need to install or remove any themes to use the normal UI.

Add optional animated themes

Check release availability first

Use a release whose Assets list the theme JSON files and whose iogw supports plugins. Older releases such as v0.1.20 do not include these packs. The screenshots show the current source build, not a promise that a compatible release has been published. If the assets are missing, use the source-build path below.

  1. 1
    Choose the same release as your binary.

    Open GitHub Releases. If upgrading, install that release's binary too; a JSON file alone cannot add a layout to an older host.

  2. 2
    Download only the scenes you want.

    Choose iogw-pixel-cafe.json, iogw-pixel-office.json, and/or iogw-pixel-station.json. Also download SHA256SUMS from that same release. Each scene is a small architecture-independent JSON file, not a second installer.

  3. 3
    Check the SHA-256.

    Compare the file's hash with its exact filename in SHA256SUMS. Use sha256sum iogw-pixel-cafe.json on Linux, shasum -a 256 iogw-pixel-cafe.json on macOS, or Get-FileHash ./iogw-pixel-cafe.json -Algorithm SHA256 in PowerShell. Repeat for each downloaded pack.

  4. 4
    Install locally.

    Run the commands below from the directory containing the downloaded files. Each theme works independently; install one, two, or all three. Packs belong on the machine running iogw, not on a remote gateway.

iogw plugins install ./iogw-pixel-cafe.json
# Optional additional scenes:
iogw plugins install ./iogw-pixel-office.json
iogw plugins install ./iogw-pixel-station.json
iogw plugins list
iogw

Press F4 or Ctrl+V to switch to the animated Overview. Press t to cycle installed themes; missing or invalid alternatives are skipped. Press Esc to return to the normal UI. Installing packs does not force animation at startup.

Build the current source

Use a repository checkout with Rust installed when the release you downloaded does not yet include animation. These commands build only the terminal client and install the source packs:

cargo build --release --locked --bin iogw
./target/release/iogw plugins install ./src/bin/iogw/plugins/pixel-cafe.json
./target/release/iogw plugins install ./src/bin/iogw/plugins/pixel-office.json
./target/release/iogw plugins install ./src/bin/iogw/plugins/pixel-station.json
./target/release/iogw

Start a local gateway separately using the quick start, or pass --base-url to connect to an existing gateway. Windows source builds produce target/release/iogw.exe.

Use only the TUI with a remote gateway

There is no dedicated TUI-only release installer today. Download the matching platform archive, verify it against the release's SHA256SUMS, and extract only iogw (iogw.exe on Windows) to a directory on PATH. You do not need to start a local gateway:

iogw --base-url https://your-gateway.example.com

Use HTTPS for remote access. Configure gateway administrator authentication before exposing its listener. Press o when login is required; a gateway administrator key and TOTP are separate from client/proxy API keys. Do not put credentials in screenshots, command history, or shared terminal recordings.

Read the scene accurately

  • Account cats Provider-colored cats represent real accounts. Bubbles show provider and status above the email, or the account name when email is unavailable. Quota percentages and compact reset countdowns use two rows normally and at most four with a; Enter shows original complete details.
  • Gold model cat The leftmost cat lists custom model aliases, not an extra provider account.
  • Gateway metrics The TV/board shows requests, tokens, accounts, error rate, and context traffic over 24 hours. Context traffic is not a model's context-window fullness.
  • LOCAL machine CPU, GPU, RAM, disk, and network readings describe the machine running iogw, not a remote gateway. Linux and macOS are supported; unsupported or inaccessible counters show N/A. History is not fabricated.
  • Decorative motion Sleeping, jumping, rolling cats, rain, and trains do not prove an account is busy. Status text remains the source of truth. Empty gateways may show resident cats without account bubbles.
  • Login feedback Every theme uses the same floating padlock and host cat. A key turns only during real login/session verification. Confirmed authentication opens the lock; failure stays locked with a retry cue and the actual error in the footer.

Data refresh and quota details

Sections load independently in the background so navigation stays responsive. Visible usage refreshes every 5 seconds, accounts and quota snapshots every 15 seconds, charts every 30 seconds, and custom models every 60 seconds. Keys and notification settings normally load only while their tab is open and refresh every 30 seconds. Failed sections retain their last values; footer ages describe when the client received each section, not when a provider last measured its quota.

r refreshes the focused Overview account; in other tabs it refreshes the current data. R reads all dashboard sections without forcing upstream quotas. Ctrl+R requests fresh server quotas for all accounts and reloads dashboard data; most terminals encode Ctrl+Shift+R identically. Repeated refreshes share outstanding requests. Focused account refresh requires a credential-file identity and never silently refreshes everyone instead. Grok quotas remain passive and header-derived: refresh does not make a paid probe request.

The gateway's quota endpoints and authenticated /dashboard/snapshot.json expose a quota_summary array of {label, value} fields when data is available. The Enter modal uses these allowlisted fields in both UIs, with a local projection for older gateways. They include reported limits, counts, percentages, balances, plans, and extra-usage metadata without credentials or raw response dumps. Updating only the terminal cannot recover data an older gateway discarded.

Bubble labels are shortened without dropping model versions, periods, or scopes: Code Gen 5h becomes Gen 5h, and MiniMax's 5h window becomes 5h. Reset countdowns use at most two time units, such as 1d2h or 1h23m. Unknown resets show a dash; missing quota is unavailable, never a fabricated zero. Overview buckets take priority over redundant model limits, but a more-used model limit is retained. Enter shows the complete details.

Local hardware measurements

Sampling runs off the drawing thread once per second, stops outside the animated Overview, and can continue while motion is paused. CPU, GPU, and RAM history bars use a fixed 0–100% scale with up to 120 real samples; unavailable samples leave gaps. Disk capacity describes the root filesystem, while read/write rates cover whole physical disks. Network rates describe one default-route interface, not a sum that double-counts bridges or VPNs. Rates require two samples.

Linux metrics use /proc, /sys, and filesystem counters. macOS uses bundled top, vm_stat, df, netstat, route, and I/O Registry counters, including Apple GPU utilization. Linux GPU readings support AMD/DRM, a timeout-bounded nvidia-smi query, and Intel i915/xe. Intel uses native performance counters when already permitted, otherwise accessible process DRM engine counters. An asterisk and readable clients identify that fallback: it may cover only part of the machine and differ from privileged btop. Shared Intel or Apple unified memory is not presented as dedicated VRAM. No sudo, capability, or kernel-permission change is required or performed; unsupported platforms and inaccessible counters stay unavailable.

Terminal support and reduced motion

A true-color terminal with Unicode half-block characters gives the clearest result. No Kitty graphics protocol, Nerd Font, desktop application, or extra animation runtime is needed. Compact layouts prioritize readable data and may omit scenery. Scene motion is capped at 20 FPS; data polling continues when paused.

# Linux/macOS: enter animation with motion paused by default.
IOGW_REDUCED_MOTION=1 iogw
# Windows PowerShell:
$env:IOGW_REDUCED_MOTION = "1"
iogw

Space pauses or resumes motion during the session. A successful login confirmation still dismisses while paused.

Update, remove, or troubleshoot packs

Update a theme by verifying and installing its replacement JSON again. Re-enter animation or change theme to reload it. The selected theme is remembered locally; removing a pack does not delete gateway accounts, credentials, or the normal UI.

iogw plugins list
iogw plugins remove pixel-cafe
iogw plugins remove pixel-office
iogw plugins remove pixel-station
  • No plugins command Upgrade the host binary to a compatible release, or build the current source. Downloading a pack alone is not enough.
  • Animation unavailable Confirm that iogw plugins list shows a valid installed pack for the same user/config environment. A missing or invalid file leaves the normal UI available.
  • Can't change themes Install another compatible pack; a single-theme installation is valid.
  • Login required Use o or iogw login for the chosen gateway. Theme installation does not authenticate you.
  • GPU or other hardware says N/A It can be unsupported, inaccessible, or waiting for a second sample. Do not treat unknown values as zero or grant elevated permissions just to enable decoration.
  • Room appears monochrome Check true-color support and whether your shell sets NO_COLOR. That variable disables terminal colors; use a color-enabled shell for the pixel-art scenes.

Scene pack format and artwork

Renderer, loader, and source artwork live together under src/bin/iogw/; there is no second application or desktop project. Only the lightweight renderer is compiled into the client. Release CI packages each JSON separately with checksums, and scene API version 1 packs work across supported architectures. New host layouts still require a compatible binary.

Packs are validated palette/sprite JSON limited to 256 KiB, not native libraries or JavaScript extensions. Palette and sprite dimensions are checked. A pack cannot execute code, read your credentials, call the gateway, fetch external resources, or add a new host layout on its own. Missing or invalid packs leave the normal UI available and report a local error.

The Café's visual direction is inspired by Metrocity's cat café; Station adapts the composition of this train-station pixel-art reference. Scenes use original code-drawn artwork and JSON sprites, not redistributed reference images, Pixel Agents artwork, or fonts. Unlike Metrocity's Kitty-protocol graphics, these scenes use terminal-resolution Unicode half-block pixels rather than aiming for a pixel-identical reproduction.
