01 / route

The first decision happens before traffic leaves your machine.

A request is checked against the client key and route policy first. Only then does IO Gateway choose a provider account that can actually take the work.

01
Authenticate the client keyReject disabled keys and apply whole-key, provider, or account prompt limits before dispatch.
02
Resolve the intended routeNormalize the client surface and turn direct models or ctm: aliases into a route intent.
03
Select an eligible accountPrefer marked accounts, then account for quota, cooldown, scope, availability, and fallback order.
04
Relay and record the outcomeStream the response back while preserving the selected account’s usage, error, and notification state.
The gateway is the boundary. Clients get one scoped key; provider credentials stay in the local operator surface.

02 / controls

The route is a policy you can inspect, not a hopeful fallback list.

The dashboard puts the inputs to routing in front of the operator: which accounts run first, which clients can ask for what, and how a stable custom route behaves.

A / priority accounts

Use the accounts you choose first—without sending work to one that is unavailable.

Mark a provider account as priority when you want it drained before the ordinary pool. Its current status still matters, so a disabled, cooling-down, or exhausted account is skipped instead of becoming a dead end.

  • Priority changes selection order, not the safety checks.
  • Usage windows and reset points stay visible next to the account.
  • Fallback accounts are explicit when the first choice cannot run.

B / client keys

A client key is a bounded contract, not a pass-through credential.

Give each client access only to the providers, accounts, and request sizes that make sense. The gateway performs those checks before upstream accounts see a prompt.

  • Set a whole-key prompt ceiling for every route behind a key.
  • Apply different limits for a provider or a single account.
  • Restrict a key to direct targets or selected custom aliases.

C / custom routes

Publish a stable name while the provider pool behind it changes.

A ctm: model is a routing rule rather than another provider list: ordered steps, weighted targets, exact account selection, exclusions, and fallback.

  • Keep a familiar client-facing model name during provider changes.
  • Mix provider targets and account-specific steps in one alias.
  • Test the same route a client will use before publishing its key.

03 / endpoints

Keep the client surface familiar. Change the route behind it.

Point the tool you already use at a localhost base URL. IO Gateway keeps the compatible protocol edge separate from provider choice and account state.

/v1
OpenAI-compatible clients. Responses, Chat Completions, Models, and direct or custom model routes.
/codex
Codex-style sessions. Gateway account selection and quota state behind a dedicated Codex surface.
/claude
Anthropic-style messages. The same local key, routing policy, and operator controls.
ctm:
Custom aliases. A stable model reference backed by the ordered targets and fallbacks you decide.

Supported provider prefixes include cod:, cld:, gem:, qwn:, glm:, and ctm:.

04 / install

Install a native build. Answer the questions that affect your machine.

The release installer selects the matching archive, verifies it, preserves an existing data directory, and makes first-run setup deliberate rather than hidden.

Linux / macOS 
bash -c 'set -o pipefail; curl -fsSL https://github.com/giofahreza/io-gateway/releases/latest/download/install.sh | sh'
Windows PowerShell 
irm https://github.com/giofahreza/io-gateway/releases/latest/download/install.ps1 | iex
binary
Native x86_64 and ARM64 releases. Linux, macOS, and Windows installers pick the right archive for the current machine.
port
Choose the local port. Keep the suggested value or use a port that fits an existing desktop setup.
autostart
Opt in to start at sign-in. The installer offers a user systemd service, LaunchAgent, or Scheduled Task when supported.
terminal
Choose whether to add the iogw TUI. The optional companion is installed only when you want it.
network
Start localhost-only. Configure administrator authentication before deliberately exposing the operator UI.

Each release includes the installers, native archives, and SHA256SUMS. The first install is interactive; documented flags cover repeatable unattended installs.
